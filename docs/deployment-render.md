# Deploying to Render

Everything is declared in `render.yaml` at the repo root — one Blueprint
creates all five resources. Your existing Render projects are untouched.

## One-time cost note (honesty)

| Resource | Plan in blueprint | Cost |
|---|---|---|
| Web (Next.js) | free | $0 (sleeps when idle, ~50s cold start) |
| API (FastAPI) | free | $0 (same sleep behaviour) |
| PostgreSQL | free | $0 for 90 days, then expires |
| Worker | starter | ~$7/mo — **no free tier exists** |
| Redis Key Value | starter | paid — no free tier |

Cheapest honest demo alternative: delete the worker + redis blocks, use a
free Upstash Redis for `REDIS_URL`, and run the worker locally for demos.

## Deploy in 4 steps

1. **Render Dashboard → New → Blueprint** → connect GitHub → pick
   `Mani78506/ContentCal` → Render reads `render.yaml` and lists all 5
   resources → **Apply**.

2. **Run migrations once** (from your PC, or Render Shell on the API service):
   ```bash
   # Render → contentcal-db → Connect → copy "External Database URL"
   # Windows PowerShell:
   $env:DATABASE_URL="postgresql+asyncpg://<user>:<pw>@<host>/<db>"
   .venv\Scripts\alembic upgrade head
   ```
   (The config normalizes any `postgres://`/`postgresql://` form automatically.)

3. **Verify wiring**:
   - `https://contentcal-api.onrender.com/health` → `{"status":"ok"}`
   - `https://contentcal-web.onrender.com` → register → connect dev account.

4. **Prove the pipeline**: schedule a post ~2 minutes out → it flips to
   `published` (the worker + Redis do this for real). Check
   **Settings → Publishing pipeline** for the job and its attempt.

## How the pieces talk

```
browser ──HTTPS──▶ contentcal-web (Next.js)
                      │ server-side rewrite /api/*  (first-party cookies ✓)
                      ▼
                 contentcal-api ──▶ contentcal-db (Postgres)
                      │ enqueue            ▲
                      ▼                    │ durable fallback
                 contentcal-redis ──▶ contentcal-worker ──▶ providers
```

- Web → API uses Render **private networking** (`hostport` reference,
  `http://` added by `next.config.ts`) — internal traffic is free & fast.
- Secrets (`JWT_SECRET_KEY`, `TOKEN_ENCRYPTION_KEY`) are auto-generated by
  Render (`generateValue`), never in the repo.

## First-run checks if something's red

- API deploy fails on build → `pip install -e "packages/core"` missing
  (it's in the blueprint's buildCommand).
- API 500 on register → migrations not run (step 2).
- Web loads but login spins → `API_INTERNAL_URL` — confirm it resolves to
  the internal API host (Render shows env value in the service's Env tab).
- Worker crash-loops → Redis URL missing or DB unreachable.
- Cold-start spin-down on free web services is normal for a demo.
